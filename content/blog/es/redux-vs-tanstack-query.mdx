Si conoces Redux y quieres entender TanStack Query (anteriormente React Query), o viceversa, esta guía te muestra **cuándo y cómo usar cada herramienta**. No se trata de decir cuál es mejor, sino de entender que resuelven problemas diferentes: Redux maneja estado global de la aplicación; TanStack Query se especializa en estado asíncrono del servidor. Las referencias oficiales son [Redux](https://redux.js.org/) y [TanStack Query](https://tanstack.com/query).

En este artículo usamos **Redux Toolkit** (la forma oficial recomendada de escribir Redux) y **TanStack Query v5** con React.

## 1. Filosofías y casos de uso

**Redux** es una biblioteca para gestión de estado global predecible. Maneja el estado de tu aplicación en un store centralizado, con actualizaciones a través de actions y reducers. Es ideal para: estado de UI complejo, datos compartidos entre muchos componentes, lógica de negocio que no depende de servidor, historial de acciones (time-travel debugging).

**TanStack Query** es una biblioteca para gestión de estado asíncrono del servidor. Maneja fetching, caching, sincronización y actualización de datos del servidor de forma declarativa. Es ideal para: datos del servidor (API calls), sincronización automática, caché inteligente, optimistic updates, revalidación en background, infinite scroll y paginación.

**Principio clave**: Redux maneja estado de cliente (UI, preferencias, sesión); TanStack Query maneja estado del servidor (datos remotos). Puedes (y a menudo debes) usar ambos juntos.

## 2. Estado global vs Estado del servidor

### Redux: Estado global centralizado

```tsx
// userSlice.ts
import { createSlice } from "@reduxjs/toolkit";

const userSlice = createSlice({
  name: "user",
  initialState: {
    data: null,
    loading: false,
    error: null,
  },
  reducers: {
    fetchUserStart: (state) => {
      state.loading = true;
    },
    fetchUserSuccess: (state, action) => {
      state.loading = false;
      state.data = action.payload;
    },
    fetchUserError: (state, action) => {
      state.loading = false;
      state.error = action.payload;
    },
  },
});

export const { fetchUserStart, fetchUserSuccess, fetchUserError } =
  userSlice.actions;
export default userSlice.reducer;
```

```tsx
// store.ts
import { configureStore } from "@reduxjs/toolkit";
import userReducer from "./userSlice";

export const store = configureStore({
  reducer: {
    user: userReducer,
  },
});
```

```tsx
// UserProfile.tsx
import { useDispatch, useSelector } from "react-redux";
import { useEffect } from "react";
import { fetchUserStart, fetchUserSuccess, fetchUserError } from "./userSlice";

function UserProfile() {
  const dispatch = useDispatch();
  const { data, loading, error } = useSelector((state) => state.user);

  useEffect(() => {
    const fetchUser = async () => {
      dispatch(fetchUserStart());
      try {
        const res = await fetch("/api/user");
        const user = await res.json();
        dispatch(fetchUserSuccess(user));
      } catch (err) {
        dispatch(fetchUserError(err.message));
      }
    };
    fetchUser();
  }, [dispatch]);

  if (loading) return <p>Cargando...</p>;
  if (error) return <p>Error: {error}</p>;
  return <p>{data?.name}</p>;
}
```

En Redux controlas manualmente: cuándo hacer el fetch, estados de loading/error, actualizar el store, y gestionar el caché. Mucho boilerplate para operaciones async.

### TanStack Query: Estado del servidor simplificado

```tsx
// UserProfile.tsx
import { useQuery } from "@tanstack/react-query";

function UserProfile() {
  const { data, isLoading, error } = useQuery({
    queryKey: ["user"],
    queryFn: async () => {
      const res = await fetch("/api/user");
      if (!res.ok) throw new Error("Network error");
      return res.json();
    },
  });

  if (isLoading) return <p>Cargando...</p>;
  if (error) return <p>Error: {error.message}</p>;
  return <p>{data?.name}</p>;
}
```

TanStack Query maneja automáticamente: caché, estados de loading/error, revalidación, refetch en background, deduplicación de requests. Mucho menos código para el mismo resultado.

| Redux                      | TanStack Query                     |
| -------------------------- | ---------------------------------- |
| Estado global centralizado | Estado del servidor con caché      |
| Manejo manual de async     | Async automático con `useQuery`    |
| Requiere actions/reducers  | Declarativo con `queryKey/queryFn` |
| Boilerplate extenso        | API minimalista                    |
| Control total              | Optimizaciones automáticas         |

## 3. Mutaciones: Actualizar datos

### Redux: Thunks para operaciones async

```tsx
// userSlice.ts
import { createAsyncThunk, createSlice } from "@reduxjs/toolkit";

export const updateUser = createAsyncThunk(
  "user/update",
  async (userData, { rejectWithValue }) => {
    try {
      const res = await fetch("/api/user", {
        method: "PUT",
        body: JSON.stringify(userData),
      });
      return await res.json();
    } catch (err) {
      return rejectWithValue(err.message);
    }
  },
);

const userSlice = createSlice({
  name: "user",
  initialState: { data: null, loading: false, error: null },
  reducers: {},
  extraReducers: (builder) => {
    builder
      .addCase(updateUser.pending, (state) => {
        state.loading = true;
      })
      .addCase(updateUser.fulfilled, (state, action) => {
        state.loading = false;
        state.data = action.payload;
      })
      .addCase(updateUser.rejected, (state, action) => {
        state.loading = false;
        state.error = action.payload;
      });
  },
});

export default userSlice.reducer;
```

```tsx
// UpdateUserForm.tsx
import { useDispatch, useSelector } from "react-redux";
import { updateUser } from "./userSlice";

function UpdateUserForm() {
  const dispatch = useDispatch();
  const { loading } = useSelector((state) => state.user);

  const handleSubmit = (data) => {
    dispatch(updateUser(data));
  };

  return <form onSubmit={handleSubmit}>...</form>;
}
```

### TanStack Query: Mutations con invalidación automática

```tsx
// UpdateUserForm.tsx
import { useMutation, useQueryClient } from "@tanstack/react-query";

function UpdateUserForm() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: async (userData) => {
      const res = await fetch("/api/user", {
        method: "PUT",
        body: JSON.stringify(userData),
      });
      return res.json();
    },
    onSuccess: () => {
      // Invalida y refetch automático de queries relacionadas
      queryClient.invalidateQueries({ queryKey: ["user"] });
    },
  });

  const handleSubmit = (data) => {
    mutation.mutate(data);
  };

  return (
    <form onSubmit={handleSubmit}>
      {mutation.isPending && <p>Actualizando...</p>}
      {mutation.isError && <p>Error: {mutation.error.message}</p>}
      {/* form fields */}
    </form>
  );
}
```

TanStack Query invalida el caché automáticamente después de mutaciones exitosas, refetcheando datos actualizados. Redux requiere lógica manual.

## 4. Optimistic Updates

### Redux: Actualización manual con rollback

```tsx
// userSlice.ts
import { createAsyncThunk, createSlice } from "@reduxjs/toolkit";

const userSlice = createSlice({
  name: "user",
  initialState: { data: null, loading: false, error: null },
  reducers: {
    setUser: (state, action) => {
      state.data = action.payload;
    },
  },
});

export const updateUser = createAsyncThunk(
  "user/update",
  async (userData, { dispatch, getState, rejectWithValue }) => {
    const previousData = getState().user.data;

    // Optimistic update
    dispatch(userSlice.actions.setUser(userData));

    try {
      const res = await fetch("/api/user", {
        method: "PUT",
        body: JSON.stringify(userData),
      });
      return await res.json();
    } catch (err) {
      // Rollback manual
      dispatch(userSlice.actions.setUser(previousData));
      return rejectWithValue(err.message);
    }
  },
);

export default userSlice.reducer;
```

### TanStack Query: Optimistic updates integrados

```tsx
// UpdateUserForm.tsx
import { useMutation, useQueryClient } from "@tanstack/react-query";

function UpdateUserForm() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: async (newData) => {
      const res = await fetch("/api/user", {
        method: "PUT",
        body: JSON.stringify(newData),
      });
      return res.json();
    },
    onMutate: async (newData) => {
      // Cancela refetch en curso
      await queryClient.cancelQueries({ queryKey: ["user"] });

      // Snapshot del valor anterior
      const previousUser = queryClient.getQueryData(["user"]);

      // Actualización optimista
      queryClient.setQueryData(["user"], newData);

      // Retorna contexto con snapshot para rollback
      return { previousUser };
    },
    onError: (err, newData, context) => {
      // Rollback automático con el snapshot
      queryClient.setQueryData(["user"], context.previousUser);
    },
    onSettled: () => {
      // Refetch para asegurar sincronización
      queryClient.invalidateQueries({ queryKey: ["user"] });
    },
  });

  return <form onSubmit={(data) => mutation.mutate(data)}>...</form>;
}
```

TanStack Query tiene primitivas específicas para optimistic updates con rollback automático. En Redux debes implementar toda la lógica manualmente.

## 5. Caché y refetching

### Redux: Caché manual

```tsx
// userSlice.ts
import { createSlice } from "@reduxjs/toolkit";

const userSlice = createSlice({
  name: "user",
  initialState: {
    data: null,
    lastFetch: null,
    loading: false,
  },
  reducers: {
    fetchUserSuccess: (state, action) => {
      state.data = action.payload;
      state.lastFetch = Date.now();
      state.loading = false;
    },
  },
});

export default userSlice.reducer;
```

```tsx
// UserProfile.tsx
import { useEffect } from "react";
import { useDispatch, useSelector } from "react-redux";

function UserProfile() {
  const dispatch = useDispatch();
  const { lastFetch } = useSelector((state) => state.user);
  const CACHE_TIME = 5 * 60 * 1000; // 5 minutos

  useEffect(() => {
    if (!lastFetch || Date.now() - lastFetch > CACHE_TIME) {
      dispatch(fetchUser());
    }
  }, [dispatch, lastFetch]);

  // ... resto del componente
}
```

### TanStack Query: Caché inteligente automático

```tsx
// UserProfile.tsx
import { useQuery } from "@tanstack/react-query";

function UserProfile() {
  const { data } = useQuery({
    queryKey: ["user"],
    queryFn: async () => {
      const res = await fetch("/api/user");
      return res.json();
    },
    staleTime: 5 * 60 * 1000, // Datos válidos por 5 minutos
    gcTime: 10 * 60 * 1000, // Garbage collection después de 10 minutos
    refetchOnWindowFocus: true, // Refetch al volver a la ventana
    refetchOnReconnect: true, // Refetch al reconectar
    retry: 3, // Reintenta 3 veces en caso de error
  });

  // ... resto del componente
}
```

TanStack Query gestiona caché, stale time, garbage collection, y revalidación automáticamente. Redux requiere implementación manual.

## 6. Paginación e infinite scroll

### Redux: Implementación manual compleja

```tsx
// postsSlice.ts
import { createSlice } from "@reduxjs/toolkit";

const postsSlice = createSlice({
  name: "posts",
  initialState: {
    items: [],
    page: 1,
    hasMore: true,
    loading: false,
  },
  reducers: {
    appendPosts: (state, action) => {
      state.items = [...state.items, ...action.payload.posts];
      state.hasMore = action.payload.hasMore;
      state.page += 1;
    },
  },
});

export const { appendPosts } = postsSlice.actions;
export default postsSlice.reducer;
```

```tsx
// PostList.tsx
import { useDispatch, useSelector } from "react-redux";
import { appendPosts } from "./postsSlice";

function PostList() {
  const dispatch = useDispatch();
  const { items, page, hasMore, loading } = useSelector((state) => state.posts);

  const loadMore = async () => {
    const res = await fetch(`/api/posts?page=${page}`);
    const data = await res.json();
    dispatch(appendPosts(data));
  };

  return (
    <>
      {items.map((post) => (
        <Post key={post.id} {...post} />
      ))}
      {hasMore && <button onClick={loadMore}>Cargar más</button>}
    </>
  );
}
```

### TanStack Query: Infinite queries integradas

```tsx
// PostList.tsx
import { useInfiniteQuery } from "@tanstack/react-query";

function PostList() {
  const { data, fetchNextPage, hasNextPage, isFetchingNextPage } =
    useInfiniteQuery({
      queryKey: ["posts"],
      queryFn: async ({ pageParam = 1 }) => {
        const res = await fetch(`/api/posts?page=${pageParam}`);
        return res.json();
      },
      getNextPageParam: (lastPage, pages) => {
        return lastPage.hasMore ? pages.length + 1 : undefined;
      },
      initialPageParam: 1,
    });

  return (
    <>
      {data?.pages.map((page) =>
        page.posts.map((post) => <Post key={post.id} {...post} />),
      )}
      {hasNextPage && (
        <button onClick={() => fetchNextPage()} disabled={isFetchingNextPage}>
          {isFetchingNextPage ? "Cargando..." : "Cargar más"}
        </button>
      )}
    </>
  );
}
```

`useInfiniteQuery` maneja automáticamente: paginación, concatenación de páginas, loading states, y gestión de "siguiente página".

## 7. Estado derivado y selectores

### Redux: Selectores con Reselect

```tsx
// todosSlice.ts
import { createSlice, createSelector } from "@reduxjs/toolkit";

const todosSlice = createSlice({
  name: "todos",
  initialState: { items: [] },
  reducers: {
    // ... reducers
  },
});

// Selector memoizado
export const selectCompletedTodos = createSelector(
  [(state) => state.todos.items],
  (todos) => todos.filter((todo) => todo.completed),
);

export default todosSlice.reducer;
```

```tsx
// CompletedTodos.tsx
import { useSelector } from "react-redux";
import { selectCompletedTodos } from "./todosSlice";

function CompletedTodos() {
  const completedTodos = useSelector(selectCompletedTodos);

  return (
    <ul>
      {completedTodos.map((todo) => (
        <li key={todo.id}>{todo.text}</li>
      ))}
    </ul>
  );
}
```

### TanStack Query: Select option

```tsx
// CompletedTodos.tsx
import { useQuery } from "@tanstack/react-query";

function CompletedTodos() {
  const { data: completedTodos } = useQuery({
    queryKey: ["todos"],
    queryFn: async () => {
      const res = await fetch("/api/todos");
      return res.json();
    },
    select: (todos) => todos.filter((todo) => todo.completed),
  });

  return (
    <ul>
      {completedTodos?.map((todo) => (
        <li key={todo.id}>{todo.text}</li>
      ))}
    </ul>
  );
}
```

Ambos memorizan transformaciones de datos, pero TanStack Query lo hace de forma integrada en la query.

## 8. Normalización de datos

### Redux: Normalización con RTK

```tsx
// usersSlice.ts
import { createEntityAdapter, createSlice } from "@reduxjs/toolkit";

const usersAdapter = createEntityAdapter();

const usersSlice = createSlice({
  name: "users",
  initialState: usersAdapter.getInitialState(),
  reducers: {
    usersReceived: usersAdapter.setAll,
  },
});

export const { usersReceived } = usersSlice.actions;

// Selectores generados automáticamente
export const {
  selectAll: selectAllUsers,
  selectById: selectUserById,
  selectIds: selectUserIds,
} = usersAdapter.getSelectors((state) => state.users);

export default usersSlice.reducer;
```

### TanStack Query: Queries individuales + caché compartido

```tsx
// hooks/useUsers.ts
import { useQuery, useQueryClient } from "@tanstack/react-query";

export function useUsers() {
  const queryClient = useQueryClient();

  return useQuery({
    queryKey: ["users"],
    queryFn: async () => {
      const res = await fetch("/api/users");
      return res.json();
    },
    onSuccess: (users) => {
      // Pre-populate caché individual
      users.forEach((user) => {
        queryClient.setQueryData(["user", user.id], user);
      });
    },
  });
}

export function useUser(userId) {
  const queryClient = useQueryClient();

  return useQuery({
    queryKey: ["user", userId],
    queryFn: async () => {
      const res = await fetch(`/api/users/${userId}`);
      return res.json();
    },
    initialData: () => {
      // Intenta obtener de la lista en caché
      return queryClient
        .getQueryData(["users"])
        ?.find((user) => user.id === userId);
    },
  });
}
```

```tsx
// UserList.tsx
import { useUsers } from "./hooks/useUsers";

function UserList() {
  const { data: users } = useUsers();
  return (
    <ul>
      {users?.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

Redux tiene herramientas integradas para normalización. TanStack Query usa estrategias de caché compartido entre queries.

## 10. Setup y configuración

### Redux: Store setup

```tsx

  reducer: {
    users: usersReducer,
    posts: postsReducer,

  middleware: (getDefaultMiddleware) =>
    getDefaultMiddleware({
      serializableCheck: false,
    }),

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
```

## 11. Tabla de referencia rápida

| Concepto           | Redux                    | TanStack Query            |
| ------------------ | ------------------------ | ------------------------- |
| Propósito          | Estado global de cliente | Estado del servidor       |
| Fetch de datos     | Manual con thunks        | `useQuery`                |
| Mutaciones         | Actions + reducers       | `useMutation`             |
| Caché              | Manual                   | Automático e inteligente  |
| Loading states     | Manual en reducers       | `isLoading`, `isPending`  |
| Refetch automático | No (manual)              | Sí (configurable)         |
| Optimistic updates | Manual con rollback      | Integrado con `onMutate`  |
| Paginación         | Manual                   | `useInfiniteQuery`        |
| Normalización      | `createEntityAdapter`    | Estrategias de caché      |
| DevTools           | Redux DevTools           | React Query DevTools      |
| Sincronización     | No automática            | Automática (window focus) |
| Boilerplate        | Alto                     | Bajo                      |

## 12. Cuándo usar cada uno

### Usa Redux cuando:

- Necesitas estado global complejo de UI (tema, preferencias, sesión)
- Requieres time-travel debugging
- La lógica de negocio es principalmente del lado del cliente
- Necesitas un único source of truth para estado no-servidor
- Ya usas Redux y el código está funcionando bien

### Usa TanStack Query cuando:

- Trabajas con datos del servidor (APIs REST, GraphQL)
- Necesitas caché automático y sincronización
- Quieres optimistic updates sin boilerplate
- Implementas paginación o infinite scroll
- Necesitas revalidación automática

### Usa ambos cuando:

- Tienes estado de cliente (Redux) Y estado del servidor (TanStack Query)
- Ejemplo: tema/preferencias en Redux, datos de usuario/posts en TanStack Query
- Esta es la arquitectura más común en aplicaciones modernas

## 13. Migración y convivencia

### Patrón común: Redux + TanStack Query

```tsx
// uiSlice.ts
import { createSlice } from "@reduxjs/toolkit";

const uiSlice = createSlice({
  name: "ui",
  initialState: {
    theme: "dark",
    sidebarOpen: true,
  },
  reducers: {
    toggleTheme: (state) => {
      state.theme = state.theme === "dark" ? "light" : "dark";
    },
    toggleSidebar: (state) => {
      state.sidebarOpen = !state.sidebarOpen;
    },
  },
});

export const { toggleTheme, toggleSidebar } = uiSlice.actions;
export default uiSlice.reducer;
```

```tsx
// UserDashboard.tsx
import { useQuery } from "@tanstack/react-query";
import { useDispatch, useSelector } from "react-redux";
import { toggleTheme } from "./uiSlice";

function UserDashboard() {
  // Estado del servidor con TanStack Query
  const { data: user } = useQuery({
    queryKey: ["user"],
    queryFn: async () => {
      const res = await fetch("/api/user");
      return res.json();
    },
  });

  // Estado de UI con Redux
  const theme = useSelector((state) => state.ui.theme);
  const dispatch = useDispatch();

  return (
    <div className={theme}>
      <h1>{user?.name}</h1>
      <button onClick={() => dispatch(toggleTheme())}>Cambiar tema</button>
    </div>
  );
}
```

Esta separación de responsabilidades resulta en código más limpio y mantenible.

## Conclusión

Redux y TanStack Query no son competidores directos: resuelven problemas diferentes. Redux brilla en gestión de estado global del cliente; TanStack Query sobresale en sincronización con el servidor. La arquitectura moderna de React a menudo combina ambos: Redux para UI/sesión/preferencias, TanStack Query para datos remotos.

Si estás construyendo una app nueva, considera TanStack Query para cualquier dato del servidor — reducirás significativamente el boilerplate. Si ya usas Redux, evalúa si parte de tu estado Redux es realmente "estado del servidor" que podría beneficiarse de TanStack Query.

Para profundizar, consulta la [documentación oficial de Redux](https://redux.js.org/) y la [documentación oficial de TanStack Query](https://tanstack.com/query).
