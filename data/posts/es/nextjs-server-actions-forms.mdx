Los **Server Actions** de Next.js permiten manejar formularios **sin** crear API Routes ni usar `fetch`. El navegador envía el `<form>` directo al servidor,
donde tu acción procesa los datos, valida, persiste y decide qué devolver.

**Ventajas clave**

- Menos _boilerplate_ (no hay `/api/*`).
- CSRF protegido por defecto.
- Revalidaciones y redirecciones integradas.
- Puedes combinar **validación server-side** (Zod v4) con **UX client-side** (React Hook Form).

En este post verás el flujo completo con código listo para pegar:

1. Esquema de validación con Zod v4
2. Server Action con mapeo de errores tipado
3. Form nativo con `useActionState` + `useFormStatus`
4. Variante con **React Hook Form**
5. Revalidación/redirect y buenas prácticas

## 1. Esquema de validación (Zod v4)

```tsx
// src/lib/schemas/contact.ts
import z from "zod/v4";

export const ContactSchema = z.object({
  name: z.string().min(2),
  email: z.email(),
  message: z.string().min(10),
});

export type ContactInput = z.infer<typeof ContactSchema>;
```

## 2. Server Action: validar, persistir y retornar estado

```tsx
// src/actions/contact.ts
"use server";

import { ContactInput, ContactSchema } from "@/lib/schemas/contact";
import { revalidatePath } from "next/cache";

export type ContactFormState = {
  ok: boolean;
  message?: string;
  errors?: Partial<Record<keyof ContactInput, string>>;
};

export async function submitContact(
  _prevState: ContactFormState,
  formData: FormData
): Promise<ContactFormState> {
  const raw = {
    name: formData.get("name"),
    email: formData.get("email"),
    message: formData.get("message"),
  };

  const result = ContactSchema.safeParse(raw);

  if (!result.success) {
    const { fieldErrors, formErrors } = result.error.flatten((issue) => issue.message);

    const errors = Object.fromEntries(
      Object.entries(fieldErrors).map(([k, v]) => [k, v?.[0] ?? ""])
    ) as Partial<Record<keyof ContactInput, string>>;

    return { ok: false, errors, message: formErrors[0] };
  }

  console.log(result.data);
  // await db.contact.create({ data: result.data });

  revalidatePath("/contact");

  // redirect("/contact/success");

  return { ok: true, message: "Success!" };
}
```

Puntos clave:

- El estado devuelto `({ ok, message, errors })` se usa en el cliente para pintar mensajes y errores campo a campo.
- `revalidatePath("/contact")` refresca caché/ISR si corresponde.

Formulario nativo (sin RHF), con estados de envío y respuesta:

```tsx
// src/app/contact/_components/contact-form.tsx
"use client";

import { useFormStatus } from "react-dom";
import { submitContact, type ContactFormState } from "@/actions/contact";
import { useActionState } from "react";

const initialState: ContactFormState = { ok: false };

function SubmitButton() {
  const { pending } = useFormStatus();
  return (
    <button
      type="submit"
      disabled={pending}
      className="rounded bg-black px-4 py-2 text-white disabled:opacity-50"
    >
      {pending ? "Sending..." : "Send"}
    </button>
  );
}

export default function ContactForm() {
  const [state, dispatch] = useActionState(submitContact, initialState);

  return (
    <form action={dispatch} className="space-y-4">
      <div>
        <label className="block text-sm mb-1">Name</label>
        <input name="name" className="w-full border rounded px-3 py-2" />
        {state.errors?.name && <p className="text-sm text-red-600 mt-1">{state.errors.name}</p>}
      </div>

      <div>
        <label className="block text-sm mb-1">Email</label>
        <input name="email" type="email" className="w-full border rounded px-3 py-2" />
        {state.errors?.email && <p className="text-sm text-red-600 mt-1">{state.errors.email}</p>}
      </div>

      <div>
        <label className="block text-sm mb-1">Message</label>
        <textarea name="message" rows={5} className="w-full border rounded px-3 py-2" />
        {state.errors?.message && (
          <p className="text-sm text-red-600 mt-1">{state.errors.message}</p>
        )}
      </div>

      {state.message && (
        <p className={`text-sm ${state.ok ? "text-green-700" : "text-red-600"}`}>{state.message}</p>
      )}

      <SubmitButton />
    </form>
  );
}
```

- `useActionState(action, initialState)` conecta el form con la Server Action y te devuelve el estado servidor→cliente.
- `useFormStatus()` te da `pending` para desactivar el botón y mostrar loading.

## 4. Variante con React Hook Form (validación al vuelo + Server Action)

```tsx
// src/app/contact/_components/contact-form-rhf.tsx
"use client";

import { useTransition } from "react";
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { ContactSchema, type ContactInput } from "@/lib/schemas/contact";
import { submitContact } from "@/actions/contact";

export default function ContactFormRHF() {
  const [isPending, startTransition] = useTransition();

  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting, isValid },
    reset,
  } = useForm<ContactInput>({
    resolver: zodResolver(ContactSchema),
  });

  const onSubmit = handleSubmit((values) => {
    const fd = new FormData();
    fd.set("name", values.name);
    fd.set("email", values.email);
    fd.set("message", values.message);

    startTransition(async () => {
      const res = await submitContact({ ok: false }, fd);
      if (res.ok) reset();
      alert(res.message);
    });
  });

  return (
    <form onSubmit={onSubmit} className="space-y-4">
      <div>
        <label className="block text-sm mb-1">Name</label>
        <input {...register("name")} className="w-full border rounded px-3 py-2" />
        {errors.name && <p className="text-sm text-red-600 mt-1">{errors.name.message}</p>}
      </div>

      <div>
        <label className="block text-sm mb-1">Email</label>
        <input type="email" {...register("email")} className="w-full border rounded px-3 py-2" />
        {errors.email && <p className="text-sm text-red-600 mt-1">{errors.email.message}</p>}
      </div>

      <div>
        <label className="block text-sm mb-1">Message</label>
        <textarea rows={5} {...register("message")} className="w-full border rounded px-3 py-2" />
        {errors.message && <p className="text-sm text-red-600 mt-1">{errors.message.message}</p>}
      </div>

      <button
        type="submit"
        disabled={isSubmitting || isPending || !isValid}
        className="rounded bg-black px-4 py-2 text-white disabled:opacity-50"
      >
        {isSubmitting || isPending ? "Sending..." : "Send"}
      </button>
    </form>
  );
}
```

Aquí RHF valida en cliente (UX rápida) y, al enviar, creamos `FormData` y llamamos directo a la misma Server Action (`submitContact`) —sin API Route—.

## 5. Revalidación, redirect y recomendaciones

- **Revalidación:** usa `revalidatePath("/contact")` si tu acción modifica datos visibles en esa ruta.
- **Redirect:** para flujo post-envío, `redirect("/contact/success")` dentro de la acción (entonces no devuelvas estado).
- **Accesibilidad:** añade `aria-invalid`, `aria-describedby` y `id`/`htmlFor` en inputs/labels.
- **UI:** sustituye el alert() por un toast/snackbar.

## Conclusión

- Los Server Actions simplifican formularios en Next.js: menos capas, seguridad integrada y gran DX.
- Zod v4 te da validación sólida (con mapeo de errores claro) y RHF aporta una UX fluida.
- Con `useActionState`/`useFormStatus` controlas estados de envío y mensajes; con `revalidatePath`/`redirect` cierras el flujo sin esfuerzo.
